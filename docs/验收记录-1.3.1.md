# 搜猫五笔 1.3.1：SecureCRT 兼容性修复

日期：2026-10-23。测试环境：Apple Silicon、macOS 27.0.1、SecureCRT 9.5.1 / Qt 6.5。

## 问题与修复

用户报告 SecureCRT 中中文、英文均无法正常输入，进一步确认仅 a 等少数按键可用。旧版未在输入会话激活时提供底层键盘布局；自定义输入源本身不含 Unicode 键盘布局数据。

Qt 6.5 的 `QAppleKeyMapper::updateKeyboard()` 优先读取 `TISCopyInputMethodKeyboardLayoutOverride()`，否则取当前输入源；随后读取 `kTISPropertyUnicodeKeyLayoutData`。`keyMapForKey()` 使用该数据调用 `UCKeyTranslate()`。因此缺少布局会影响客户端把按键送进输入法之前的键盘转换。

修复仅在 `SoumaoInputController.activateServer` 中为每个客户端调用 `overrideKeyboard(withKeyboardNamed: "com.apple.keylayout.ABC")`，并在每次重新激活时重设。五笔、拼音和英文共用标准 ABC 底层布局；英文及应用控制快捷键继续按原规则透传。

参考：
- Apple SDK `Carbon.framework/Frameworks/HIToolbox.framework/Headers/IMKInputSession.h` 的 `overrideKeyboardWithKeyboardNamed:`，要求在每次激活时调用。
- https://github.com/qt/qtbase/blob/v6.5.3/src/gui/platform/darwin/qapplekeymapper.mm

## 实机证据

修复前，用户确认仅 a 可输入；输入法日志在相应测试区间只收到 a、空格和修饰键，而其他应用能收到完整字母。临时诊断日志曾错误读取鼠标事件的 keyCode；该诊断错误已修正，不在正式源码中，未将它当作产品根因。

修复后，通过已注册输入源运行含布局修复的诊断副本，用户在独立的 `Soumao-IME-VERIFY` 连接中执行：中文模式 `lwty`＋空格、Shift 切英文、`abcxyz123`。本机 127.0.0.1:65054 接收端（仅回显，无 shell）实际收到：

```text
输入abcxyz123
UTF-8: e8be93e585a561626378797a313233
```

可机器核对的结果：`build/securecrt-input-1.3.1.json`。它验证了中文提交及英文/数字真正抵达终端接收端，并非只检查输入法是否调用提交方法。该次修复前后结果与 Qt 源码相互支持；未对 Qt 内部执行做原生函数跟踪。
